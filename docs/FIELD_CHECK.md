# Проверка на площадке

Полевые измерения и успешность конкурсной попытки ещё не подтверждены файлами.
Шаблоны ниже не являются результатами испытания.

## Координаты

Используется карта `drone/aruco_nav/aruco_map_750x450_id100.txt`:
метры, начало в центре поля, DICT_4X4_1000, ID 100–144.
ID выбирает готовые x/y/z из карты. Пиксельный центр коробки не является
координатой аппарата. Формула ID → строка карты не доказывает точность локализации.

Для пяти точек в `coordinate_check.csv` измерить координаты центров маркеров
относительно того же начала и осей. Записать дату, исполнителя и ошибку
`sqrt((map_x-measured_x)^2 + (map_y-measured_y)^2)`.
Указать масштаб/ориентацию карты в конфигурации аппаратуры, требуемую точность
из задания и максимальную/RMSE ошибку. Записать контрольный полёт и фактическую
телеметрию в `aruco_map`; сопоставить её с независимым измерением.
Ни разбор карты, ни успешная команда navigate не заменяют этот эксперимент.

## Компьютерное зрение

Сохранить независимые кадры площадки через `--save-frames` (станция включает
это автоматически). Не включать оценочные кадры в обучение. Вручную разметить
каждую коробку, включая пропущенные моделью: класс и xyxy в пикселях.
Формат JSON для `field_report.py --labels labels.json`:

```json
{"frame.jpg": [{"class_name": "box_hitech", "xyxy": [10, 20, 90, 100]}], "empty.jpg": []}
```

Пустой список означает проверенный отрицательный кадр; отсутствие имени —
отсутствие оценки. Указывать все объекты, а не только удачные находки.
Сравнить нормальные/дефектные коробки, перекрытые метки и разные ракурсы.
Фиксировать ложное «пусто» и ошибочный ID отдельно от детекции коробок.

## Сквозной запуск

Сохранить видео, `scan.log`, `observations.jsonl`, `inventory.csv` и покрытие.
Вручную составить эталон по всем ID и сравнить ведомость. Проверить потерю
одной камеры, обрыв WebSocket, повторные наблюдения и завершение посадки.
UI не показывает телеметрию заряда и не подтверждает физическое состояние
аппарата независимо от ответов его SDK. Остановку проверять с пилотом.
