# Веб-панель наземной станции

Локальный интерфейс управления двумя дронами, просмотра камер и CV. Работает на ноутбуке в сети дронов; облачная публикация не нужна. Бортовой `ws_flight.py` не изменяется.

## Запуск

Из корня проекта, в существующем venv:

```bash
python3 -m pip install -r requirements-web.txt
python3 web_station/server.py
```

Откройте **http://127.0.0.1:8766/**. Сервер команд слушает `0.0.0.0:8000`, поэтому перед запуском остановите отдельный `drone/aruco_nav/ws_control.py`, если он уже работает. Веб-сервер по умолчанию доступен только на ноутбуке (127.0.0.1).

На дронах запускаются существующие клиенты:

```bash
# Первый дрон
python3 drone/aruco_nav/ws_flight.py --server ws://IP_НОУТБУКА:8000 --id drone3
# Второй дрон
python3 drone/aruco_nav/ws_flight.py --server ws://IP_НОУТБУКА:8000 --id drone4
```

Текущие ID `drone3`/`drone4` взяты из `drone/aruco_nav/routes.example.json`. В `web_station/config.json` заданы соответствия камер: drone3 → 10.11.3.179, drone4 → 10.11.3.225. Если физическое соответствие другое, измените его до использования. Там же настраиваются карта, маршруты, веса, словарь и устройство CPU/GPU.

Другие порты:

```bash
python3 web_station/server.py --port 8766 --robot-port 8001
```

Тогда на дронах тоже нужно указать порт 8001 в `--server`. Доступ к панели с других устройств можно явно включить через `--host 0.0.0.0` только в доверенной локальной сети: пользовательской аутентификации нет. Не публикуйте управляющий интерфейс в интернет. Запросы изменения защищены ключом текущей локальной сессии и проверкой Origin; это защита от посторонних веб-страниц, а не от других пользователей сети. Протокол самих дронов также идентифицирует клиентов только по ID.

## Полёт и камеры

- При запуске и открытии страницы никаких команд не отправляется, камеры выключены.
- **Отправить цель**: X/Y/Z в aruco_map, yaw=0, скорость 0.3 м/с задана клиентом. Перед отправкой показываются конкретные координаты. Первая navigate может включить моторы и выполнить встроенный взлёт, определённый установленным бортовым скриптом.
- **Посадка**: land выбранного дрона. Если он выполняет ручную navigate, посадка ждёт её завершения. Во время общей миссии кнопка останавливает оба маршрута и выполняет посадку обоих.
- **Остановить и посадить**: остановка общей миссии либо посадка всех подключённых дронов после текущих команд. Это не мгновенная аварийная остановка. Протокол не позволяет отменить текущую navigate.
- **Маршруты**: JSON можно отредактировать либо загрузить из файла. Используется существующая validate_routes: ровно два дрона, проверка параметров и зазора не менее 0.75 м между заданными участками. Встроенный взлёт и переход к первой точке этой проверкой не покрываются. Ручные цели не проверяются на столкновения.
- Ручные команды заблокированы во время общей миссии; повторная navigate занятому дрону отклоняется. Подтверждение в журнале приходит от клиента, а не означает только отправку.
- **Включить камеры**: HTTP snapshots штатного web_video_server раз в секунду. Режим «Только камера» не загружает YOLO. Режим CV использует текущий BoxProcessor: классы боксов/аномалий, фильтр меток, сопоставление и накопление результатов. Модель общая, inference последовательный, сетевые запросы камер независимы.
- Панель показывает время последнего снимка и ошибки источника; оставшийся на экране кадр не выдаётся за свежий при разрыве связи. Телеметрия положения и моторов не отображается, потому что текущий клиент её не передаёт.
- Смена адресов камер через интерфейс действует до перезапуска и требует остановки камер. Постоянные изменения — в config.json.

## Инвентаризация

«Карта адресов» отображает существующую ArUco-карту (100–144) и состояния. «Не считано» отличается от «пусто». Последнее означает лишь отсутствие найденной коробки на кадре с видимой меткой; возможны пропуски модели.

«Скачать адреса.txt» выдаёт формат `ID: состояние`. Во время CV обновляются `runs/web_station/addresses.txt` и `addresses.coverage.json`; предыдущие результаты обычного сканера в `runs/addresses.txt` не затрагиваются. Новая сессия не подхватывает предыдущую инвентаризацию. Кнопка «Новый обход» очищает текущие результаты и доступна после остановки камер.

Закрытие вкладки не прекращает выполнение маршрутов. Останавливайте миссию кнопкой панели. Ctrl+C в терминале завершает камеры и дожидается окончания текущих команд с посадкой; это может занять время в пределах тайм-аутов старого клиента. Физическая посадка при потере связи сервером не гарантируется и не подменяет failsafe контроллера.

## Ровер

Есть отдельная вкладка со статусом будущего подключения. Управление ровером намеренно не выдаётся за работающее: `rover/rover_client.py` использует `shared/WsClient` с регистрацией `ok`, тогда как дроны ожидают JSON `registered`. Следующий этап — отдельный адаптер, сервер/порт и описание параметров navigate/stop ровера. Архитектура панели отделяет командный транспорт `ObservedServer`, состояние `Station`, HTTP API и интерфейс; дроновый адаптер не потребуется переписывать ради ровера.

## Проверки

```bash
python3 -m unittest discover -s web_station -p 'test_station.py' -v
```

9 тестов: страница без команд при открытии, отсутствие соединения, проверка ключа/Origin, запрет второй команды занятому дрону, отложенная посадка, некорректные координаты, остановка общей миссии, пересечение маршрутов, приём/остановка тестовых камер и экспорт/сброс (часть сценариев объединена в тестах). Используются локальные имитаторы WS-клиентов и камера-фикстура, реальные дроны не запускаются. Интерфейс также проверен в браузере с имитаторами и реальной CV-моделью на тестовой фотографии.

## Ровер

Вкладка «Ровер» использует штатный HTTP API на `http://10.11.3.195:8765`.
Адрес управления и снимков задан в секции `rover` файла `config.json`. SSH и установка программ на ровер для работы панели не нужны.

- Удерживайте стрелку для движения. Отпускание, уход с вкладки, потеря фокуса отправляют остановку.
- Команды повторяются браузером каждые 80 мс после ответа; штатный watchdog ровера (0,25 с) останавливает моторы при потере команд. Сервер сам не продлевает движение.
- «СТОП» отправляет `/api/drive/stop`. Боковое движение доступно для mecanum.
- «Включить камеру» получает JPEG `/api/camera/media/frame?mode=live` раз в секунду. Если обработка дольше секунды, очередь не накапливается.
- Режим «Камера + YOLO» выполняет `best_for_classificator(2).pt` на ноутбуке, показывает коробки и аномалии. На борт модель не устанавливается. Разметка ArUco сверху/снизу для наземной камеры не применяется, карта дронов не меняется.
- Открытие панели не включает камеру и не отправляет команды движения.

Проверки без физического движения: `.venv/bin/python -m unittest discover -s web_station -p 'test_*.py' -v`.
