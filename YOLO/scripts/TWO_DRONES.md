# Два дрона: адреса, коробки и аномалии

Запуск из корня проекта:

```bash
python3 YOLO/scripts/scan_two_drones.py --servers 'http://10.11.3.225:8080/snapshot?topic=/camera_1/image_raw' 'http://10.11.3.179:8080/snapshot?topic=/camera_1/image_raw' --interval 1
```

По умолчанию используются `best_for_classificator(2).pt`, карта `drone/aruco_nav/aruco_map_750x450_id100.txt` (100–144) и словарь DICT_4X4_1000 из её заголовка. При другой карте задайте `--map` и её словарь `--dictionary` явно. На дронах изменений не требуется.

Фото запрашиваются параллельно у двух дронов. Одна модель последовательно обрабатывает оба снимка. Новый цикл начинается не чаще раза в секунду; при медленной сети или CV интервал увеличивается, очередь не создаётся. Ошибка одной камеры выводится и записывается в отчёт, результаты второй всё равно обрабатываются. `--headless` отключает окна, `--rounds 10` завершает сбор после 10 циклов. По умолчанию работа до Ctrl+C/Q/Esc.

Расположение для сопоставления: метка сверху, коробка снизу. Центр метки должен находиться над верхней гранью коробки и в пределах её ширины. Внутренний параметр match_box_to_marker равен +90, поскольку функция преобразует координаты в локальную систему; -90 в этой функции выбирал метку снизу. Это поворот правила сопоставления, а не картинки и не команды дрону. Правило зависит от ориентации камеры; одинаковая ориентация обоих дронов предполагается.

`runs/addresses.txt` содержит строки `ID: состояние`, например:

```text
100: пусто
101: занято
102: аномалия
```

Адрес — ID ArUco из карты. Видимая метка без сопоставленной коробки получает «пусто», с обычной коробкой — «занято», с дефектной — «аномалия». Это результат CV, а не гарантия отсутствия предмета: перекрытие или недетектированная коробка могут дать ложное «пусто». Неувиденные метки не записываются как пустые.

Для каждого адреса хранятся последние 9 наблюдений коробки с двух камер. Класс выбирается суммой confidence по классам; на один адрес за кадр даётся только один голос максимальной уверенности. Ошибочный дефект теперь может быть исправлен последующими наблюдениями нормальной коробки. Отсутствие детекции не стирает ранее найденную коробку. Первый результат предварительный: несколько последовательных кадров дают более устойчивую оценку, но одинаковые ошибки модели могут повторяться. Для новой инвентаризации после перемещения коробок перезапустите программу; предыдущий результат не загружается. Старые выходные файлы перезаписываются. Уникальность соответствия меток коробкам не навязывается.

`runs/addresses.coverage.json` содержит expected_ids, read_ids, unread_ids, unknown_ids, complete, seen_by и статусы источников (последний успех и последняя ошибка). Метки вне карты в основной файл не попадают. Итоговые файлы атомарно обновляются каждый цикл и сохраняются при штатном завершении; `--output` меняет путь основного файла.

Тесты: `python3 -m unittest discover -s YOLO/scripts -p 'test_inventory.py' -v`.

## Фильтр ArUco, ошибочно распознанных как коробки

Если не менее 50% площади рамки YOLO покрывает многоугольник распознанной ArUco-метки, рамка исключается до подсчёта коробок, рисования и сопоставления. Проверяется реальный контур метки, включая поворот, а не её прямоугольная оболочка. Правило применяется к обоим классам и обоим дронам. Маленькое пересечение соседней коробки с меткой не исключает коробку.

В JSON обработчика `ignored_detections` содержит причину aruco_as_box и ID метки. Сама метка остаётся считанной для отчёта покрытия. Фильтр работает только для меток, которые декодировал ArUco-детектор; плохо видимые/непрочитанные метки он не отсекает. Порог 50% — геометрическая эвристика. Чтобы убрать ошибочные состояния, накопленные прошлой версией, перезапустите сбор: он начинает новый обход.

## Диагностика качества

В coverage.json добавлены unmatched_boxes (найденные коробки без декодированной метки) и classification_evidence (число наблюдений и суммы уверенности классов). Их нельзя считать потерянными детекциями: коробка может быть найдена, но метка перекрыта. ID скрытой метки автоматически не угадывается.

Для записи материала с обхода добавьте `--save-frames runs/scan_debug`: исходные фото, результаты и JSON записываются для каждого дрона. Каталог растёт во время работы. Нужны все ракурсы восьми коробок, чтобы оценивать полноту на всей площадке. Старайтесь оставлять всю чёрную рамку ArUco открытой и наблюдать каждый адрес несколько раз. Размер входа зафиксирован 640: на двух предоставленных примерах 960/1280 ухудшали распознавание. Порог 0.25 оставлен — его снижение добавляло ложные и повторные рамки.
