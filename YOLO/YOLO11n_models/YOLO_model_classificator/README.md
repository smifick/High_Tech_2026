## О проекте

Ноутбук дообучает предобученную модель `yolo11n.pt` на собственном датасете. Модель возвращает ограничивающие прямоугольники, классы и уверенность предсказаний для найденных объектов.

| ID | Класс | Назначение |
| --- | --- | --- |
| `0` | `box_hitech` | Коробка основного класса |
| `1` | `box_hitech_defect` | Коробка с дефектом |

Несмотря на слово `Classificator` в имени ноутбука, используется задача **детекции**: на одном изображении может быть несколько объектов. Типы дефектов и критерии их разметки в ноутбуке не описаны.

### Этапы работы

1. Установка зависимостей и подключение Google Drive.
2. Распаковка ZIP-архива с проверкой путей файлов.
3. Проверка порядка классов и подготовка выборок.
4. Проверка TXT-разметки и создание `data.yaml`.
5. Дообучение YOLO11n и сохранение результатов на Google Drive.

## Датасет и разметка

По умолчанию архив должен находиться здесь:

```text
/content/drive/MyDrive/Colab Notebooks/yolo_detecting_boxes.zip
```

Ожидаемая структура внутри архива:

```text
yolo_detecting_boxes/
├── classes.txt                 # Необязателен; порядок классов проверяется
├── images/
│   ├── train/
│   ├── val/
│   └── test/                   # Необязательная тестовая выборка
└── labels/
    ├── train/
    ├── val/
    └── test/
```

В архиве должна быть ровно одна папка датасета с соседними каталогами `images` и `labels`. Поддерживаются изображения `.jpg`, `.jpeg`, `.png`, `.bmp`, `.webp`.

### Формат аннотаций

Каждому изображению соответствует TXT-файл с тем же именем и относительным расположением: например, `images/train/box_01.jpg` → `labels/train/box_01.txt`.

Одна строка описывает один объект в формате YOLO:

```text
class_id x_center y_center width height
```

Координаты нормализованы относительно ширины и высоты изображения. Пример:

```text
0 0.50 0.50 0.30 0.40
1 0.25 0.35 0.15 0.20
```

Ноутбук проверяет наличие TXT для каждого изображения, пять числовых значений в строке, конечность чисел, ID класса `0` или `1`, центры в диапазоне `[0, 1]`, ширину и высоту в диапазоне `(0, 1]`. В каждой используемой выборке должны присутствовать объекты обоих классов. Пустой TXT допустим для изображения без объектов.

Если `classes.txt` присутствует, его содержимое должно точно соответствовать порядку:

```text
box_hitech
box_hitech_defect
```

> Изменение названий в YAML не перенумеровывает классы в TXT-разметке.

### Разделение данных

При наличии `images/train` и `images/val` ноутбук использует готовое разделение. Папка `images/test` подключается при наличии.

Если готового разделения нет, предусмотрено случайное распределение независимых фотографий:

```python
ALLOW_RANDOM_SPLIT = True
```

Пропорции: **70% train / 15% val / остаток test**, фиксированный seed — `42`. Требуется минимум 10 изображений; дополнительно после разделения проверяется наличие обоих классов в каждой выборке. По умолчанию случайное разделение отключено.

Для кадров видео заранее разделяйте данные по полётам или съёмочным сессиям, чтобы близкие кадры не попадали одновременно в обучение и оценку.

## Запуск в Google Colab

1. Загрузите архив `yolo_detecting_boxes.zip` в папку `Colab Notebooks` на Google Drive.
2. Откройте `Boxes_Classificator_YOLO(2).ipynb` в [Google Colab](https://colab.research.google.com/).
3. Для исходной конфигурации достаточно среды с CPU.
4. Выполняйте ячейки последовательно сверху вниз. В первой ячейке разрешите подключение Google Drive.
5. Проверьте напечатанный порядок классов и статистику выборок перед запуском обучения.
6. После завершения найдите результаты в `MyDrive/yolo_boxes/`.

Первая ячейка устанавливает зависимости:

```python
%pip install -q ultralytics pyyaml
```

Также используются PyTorch, модуль `google.colab` и стандартная библиотека Python. Для установки пакетов и первоначальной загрузки `yolo11n.pt` нужен доступ в интернет.

Если архив расположен иначе, измените переменную `ARCHIVE` во второй ячейке. Датасет распаковывается во временную папку `/content/yolo_boxes_<timestamp>/`; после сброса среды Colab его потребуется распаковать заново.

### Конфигурация датасета

`data.yaml` создаётся автоматически. Пример структуры:

```yaml

train: images/train
val: images/val
names:
  0: box_hitech
  1: box_hitech_defect
test: images/test
```

Поле `test` добавляется только при наличии соответствующей папки.

## Параметры обучения

| Параметр | Значение | Описание |
| --- | --- | --- |
| Начальные веса | `yolo11n.pt` | Предобученная YOLO11 nano |
| `epochs` | `50` | Максимальное число эпох |
| `imgsz` | `640` | Целевой размер входа при обработке изображений |
| `batch` | `4` | Размер пакета |
| `device` | `"cpu"` | Обучение на CPU |
| `workers` | `2` | Запрошенное число процессов загрузки данных |
| `patience` | `10` | Ранняя остановка при отсутствии улучшения критерия качества |
| `seed` | `42` | Фиксированное начальное значение генератора |
| `plots` | `True` | Сохранение графиков |
| `project` | `/content/drive/MyDrive/yolo_boxes` | Каталог результатов |
| `name` | `two_classes_cpu_<timestamp>` | Имя запуска |

В сохранённом журнале библиотека фактически использовала `0` процессов загрузки данных на CPU. Оптимизатор выбирается автоматически; в этом запуске выбран AdamW с начальным `lr=0.001667`.

> В первой ячейке задано `DEVICE = "cpu"`, но вызов `model.train()` отдельно содержит `device="cpu"`. Для перехода на GPU необходимо изменить именно аргумент обучения, например на `device=0`, и включить GPU в среде Colab.

Версии пакетов в установочной ячейке не закреплены. В сохранённом журнале указаны Ultralytics `8.4.209`, Python `3.13.18` и PyTorch `2.14.1+cpu`; это сведения о записанном запуске, а не проверенная матрица совместимости. Для повторяемых экспериментов сохраняйте версии зависимостей вместе с результатами.

## Результаты и файлы модели

Каждый запуск получает отдельную папку на Google Drive:

```text
MyDrive/yolo_boxes/two_classes_cpu_<timestamp>/
├── weights/
│   ├── best.pt                 # Лучший checkpoint по критерию валидации
│   └── last.pt                 # Последний сохранённый checkpoint
├── dataset_config.yaml         # Копия data.yaml после завершения train()
└── ...                         # Журналы, таблицы и графики Ultralytics
```

В зависимости от версии библиотеки в каталоге также могут находиться `args.yaml`, `results.csv`, `results.png`, матрицы ошибок и графики precision/recall.

После обучения ноутбук получает путь к каталогу запуска, задаёт `BEST_WEIGHTS` и сохраняет конфигурацию датасета в `dataset_config.yaml`.

### Метрики качества

Для оценки модели используются следующие метрики:

| Метрика | Что показывает |
| --- | --- |
| Precision | Долю корректных обнаружений среди предсказанных объектов |
| Recall | Долю найденных объектов среди всех размеченных объектов |
| mAP@50 | Среднюю точность детекции при пороге IoU 0.50 |
| mAP@50–95 | Среднюю точность детекции по порогам IoU от 0.50 до 0.95 |

Значения метрик и графики обучения сохраняются в каталоге запуска Ultralytics.

## Проверка и применение модели

Следующие примеры — дополнительные ячейки для запуска **после успешного обучения**. В исходном ноутбуке их нет.

### Оценка на тестовой выборке

Запускайте только при наличии `test` в созданном `data.yaml`:

```python
from ultralytics import YOLO

best_model = YOLO(str(BEST_WEIGHTS))
metrics = best_model.val(
    data=str(DATA_YAML),
    split="test",
    imgsz=640,
    batch=4,
    device="cpu",
)

print("mAP@50:", metrics.box.map50)
print("mAP@50–95:", metrics.box.map)
```

При отсутствии test используйте `split="val"`, учитывая, что эта выборка уже участвует в выборе лучшей модели. Отдельно анализируйте качество класса `box_hitech_defect`: общая метрика может скрывать пропуски дефектных коробок.

### Детекция на новом изображении

Замените `source` на путь к своему файлу:

```python
from ultralytics import YOLO

best_model = YOLO(str(BEST_WEIGHTS))
results = best_model.predict(
    source="/content/drive/MyDrive/example.jpg",
    imgsz=640,
    conf=0.25,
    device="cpu",
    save=True,
    project="/content/drive/MyDrive/yolo_boxes_predictions",
    name="demo",
)

print("Результаты:", results[0].save_dir)
```

Порог `conf=0.25` приведён для примера; подбирайте его на валидационных данных под допустимые пропуски и ложные срабатывания. В новой сессии вместо `BEST_WEIGHTS` укажите полный путь к сохранённому `weights/best.pt`. Для оценки заново подготовьте датасет: путь внутри `dataset_config.yaml` указывает на временный каталог исходной сессии.

## Решение частых проблем

| Сообщение или ситуация | Что проверить |
| --- | --- |
| `Не найден архив` | Подключение Drive, имя ZIP и значение `ARCHIVE` |
| `Ожидалась одна папка датасета` | В архиве должна быть одна пара соседних папок `images` и `labels` |
| Нет `images/train` и `images/val` | Подготовьте разделение или включите `ALLOW_RANDOM_SPLIT` для независимых фото |
| Не совпадают классы экспорта | Порядок `classes.txt` и ID в TXT; правки одного YAML недостаточно |
| Не найдена разметка | Имена и относительные пути изображений и TXT должны совпадать |
| `Некорректная разметка` | Проверьте указанный файл и строку: пять чисел, ID и диапазоны координат |
| В выборке отсутствует класс | Исправьте распределение данных, сохранив независимость выборок |
| Обучение идёт медленно | CPU ожидаемо медленнее GPU; включите GPU и измените аргумент `device` |
| После перезапуска пропали данные | Повторите подготовку датасета; веса ищите в папке проекта на Drive |

---

**Основной артефакт завершённого обучения:** `weights/best.pt`. Перед практическим использованием проверьте его на независимых данных и примерах обоих классов.
