# Миссия ровера с выездом из ниши

Координатор запускается на ноутбуке. Он читает задание от обработки кадров
двух дронов и передаёт цели штатному Nav2 на ровере по HTTP. Лидар, AMCL и
Nav2 работают на ровере. Камера передаёт кадры на ноутбук, где модель
определяет состояние боковин. Координатор сохраняет ответ в каталоге
попытки на ноутбуке.

## Файл от обработки кадров дронов

Один UTF-8 JSON на попытку после объединения результатов обоих дронов.
Записывайте его под временным именем и переименовывайте после завершения
записи. Пример из `drone_job.example.json`:

```json
{
  "schema_version": 1,
  "mission_id": "attempt-001",
  "boxes": [
    {"marker_id": 112, "anomaly": true},
    {"marker_id": 122, "anomaly": false},
    {"marker_id": 130, "anomaly": true, "offset_m": [0.30, 0.10]}
  ]
}
```

- `marker_id` — целый ID из карты ArUco. На один ID допускается одна запись.
- `anomaly: true` — нужна проверка боковин. Сюда также можно направлять
  спорные коробки, если ноутбук хочет поручить решение роверу.
- `anomaly: false` — коробка известна, её осмотр не запланирован.
  Передавайте все найденные коробки, чтобы планировщик мог объехать их.
- `offset_m` необязателен. Это вектор от центра метки до центра коробки
  по осям карты ArUco в метрах. По умолчанию используется
  `box_offset_m` из конфигурации ниши. Пустые места в файл не входят.

## Разовая настройка ниши

Скопируйте `dock.example.json` в `dock.json`. Заполните три поля:

1. `dock_pose` — центр базы в парковочной позиции и направление камеры
   при выезде из ниши, `[x, y, yaw_deg]` в координатах карты Nav2.
2. `mouth_pose` — центр базы сразу за выходом из ниши и курс по
   направлению выезда, в том же формате. Между парковочной позой и этой
   точкой должен быть свободный прямой проход.
3. `box_offset_m` — измеренное стандартное смещение коробки от её
   метки по осям ArUco.

Положение и курс измеряются на карте, где видны борта ниши. Курс
отсчитывается от +X карты Nav2 против часовой стрелки. Рисунок ниши
без масштаба и координат годится как схема. Если ниши нет на снимке
карты, снимите её штатным SLAM, сохраните версию и заново отметьте
100, 108, 136, 144 на этой версии. Укажите её путь через `--map`.
Архивный снимок `field_01.snapshot.json` и его PNG подходят для
офлайн-планирования. Фактическое положение ниши надо сверить на месте.

Программа уточняет стартовую позу по свежему скану лидара, сопоставляя
его с бортами в окрестности ниши, затем передаёт позу AMCL. Четыре
именованные точки привязывают систему координат ArUco к карте Nav2.
После выезда AMCL продолжает локализацию по карте и лидару.

`box_radius_m` — радиус круга, охватывающего коробку, с запасом на
погрешность привязки. `clearance_m` — запас вокруг центра базы с учётом
габаритов. Проверьте эти параметры по полю и доступной ширине ниши.
Программа проверяет геометрию маршрута и сверяет Nav2 с одометрией.
При расхождении локализации останавливает миссию. Фактические
препятствия обрабатывают штатные карты стоимости Nav2 по лидару.
Файл задания помогает планировать объезд заранее.

## Запуск

Из корня `High_Tech_2026` в PowerShell:

```powershell
.\.venv\Scripts\python.exe -m rover.dock_mission plan --job boxes.json --dock rover/dock.json --snapshot rover/field_01.snapshot.json --output plan.json
.\.venv\Scripts\python.exe -m rover.dock_mission run --job boxes.json --dock rover/dock.json --output attempts/attempt-001
```

План сохраняет JSON с точками и PNG для визуальной сверки. Для новой
версии карты получите снимок, когда ровер доступен:

```powershell
.\.venv\Scripts\python.exe -m rover.dock_mission snapshot --map "archive/ИМЯ/map.yaml" --output rover/field_new.snapshot.json
```

По умолчанию используется `rover/yolo_two_classes/rover-yolo-two-classes.pt`.
Можно выбрать веса через `--weights`. Ровер пытается осмотреть четыре
вертикальные грани коробки. На каждой достижимой позиции снимаются
три свежих кадра. Для решения нужна согласованная детекция. Грани
именуются `x+`, `x-`, `y+`, `y-` по сторонам коробки относительно осей ArUco.

В конце ровер возвращается через точку выхода к парковочной позе.
На возврат отводится отдельный резерв времени. При потере локализации,
связи или блокировке прохода возврат может остаться неподтверждённым.
Состояние миссии и частичные результаты сохраняются по ходу работы.

## Результат для вычислителя

Читать `attempts/<mission_id>/result.json` после завершения процесса.
Файл содержит `mission_id`, `status`, `returned_to_dock` и массив
`inspections`. Для каждой проверяемой метки в нём есть `marker_id`,
`side_anomaly` и `faces` с результатами по сторонам.

- `side_anomaly: true` — на одной или нескольких гранях найдена аномалия.
- `side_anomaly: false` — на всех четырёх гранях уверенно распознана
  обычная коробка.
- `side_anomaly: null` — аномалия не подтверждена, а одной или
  нескольких граням не удалось присвоить уверенный результат.

Кадры хранятся рядом с JSON. Вывод модели об аномалии доступен для
проверки. Текущая модель иногда пропускает трещины, поэтому требуется
полевой контроль качества.

## Полная миссия на field_01

Конфигурация rover/dock.field_01.json содержит измеренную стартовую позу,
точку передачи управления Nav2 и промежуточные точки выезда и парковки.
Перед запуском измерьте box_offset_m или передайте offset_m для каждой коробки.

Из корня проекта:

    .\.venv\Scripts\python.exe -m rover.dock_mission plan --job boxes.json --dock rover/dock.field_01.json --snapshot rover/field_01.snapshot.json --output plan.json
    .\.venv\Scripts\python.exe -m rover.dock_mission run --job boxes.json --dock rover/dock.field_01.json --output attempts/attempt-001

При выезде и парковке программа движется короткими шагами по свежему лидару
и сверяет позу между точками. Nav2 работает на основной части поля.
Статус парковки и результаты осмотра записываются в result.json.
