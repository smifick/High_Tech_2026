## Кейс 1. Наземный осмотр

Команды выполняются из корня `High_Tech_2026` в PowerShell. Используется
существующее окружение `.venv` с OpenCV, NumPy и Ultralytics. При отсутствии
зависимостей установите их из корневого `requirements.txt`.

```powershell
.\.venv\Scripts\python.exe -m rover.mission check --output field_preview.png
```

`check` читает карту, опорные точки, состояние камеры и готовность Nav2 через
веб-API ровера. Пароль для этого интерфейса не используется. Программа
работает на ноутбуке, штатные драйверы, AMCL и Nav2 работают на ровере.

Выбрана архивная карта `field_01` с временем создания
`2026-11-11T12:47:53+03:00`, разрешением 0,05 м/пиксель и четырьмя точками
100, 108, 136, 144. Преобразование ArUco → Nav2 вычисляется при каждом
запуске по этим точкам. Оно даёт поворот около 27,95°, перенос
(7,865; 8,0625) м и максимальную невязку 3,2 см на опорах.

### Подготовка и планирование

1. По фактическому положению и курсу поставьте начальную позу в координатах
   Nav2. Правый нижний угол поля ArUco находится у метки 108, около
   `(11.22, 8.14)` на карте Nav2. Используйте центр базы ровера.
   Курс задаётся в градусах от +X карты Nav2 против часовой стрелки.
   Можно указать `--start X Y YAW_DEG` или `--start-px COL ROW YAW_DEG`.
   Пиксели отсчитываются от верхнего левого угла исходной карты 197×196.
   PNG от `check` увеличен в 5 раз.
2. Измерьте смещение центра коробки относительно маркера по осям поля
   ArUco и передайте `--box-offset DX DY` в метрах. Если постановка коробок
   отличается между рядами, текущая схема с общим смещением требует
   адаптации. В примере ниже поза и смещение условные.
3. Выполните `plan` и проверьте точки и направления осмотра на PNG.
   Зелёные стрелки показывают позы съёмки, красная — начальную позу.

```powershell
.\.venv\Scripts\python.exe -m rover.mission plan --start-px 175 73 0 --box-offset 0.35 0 --ids 100 108 136 144 --output route.png
```

### Попытка

Передайте `--observations observations.jsonl` и/или `--ids`. Каждая
строка JSONL должна содержать `marker_id` и `state`. Допустимые состояния
`occupied`, `empty`, `anomaly`, `unknown`. Пример строки:

```json
{"marker_id": 108, "state": "anomaly", "drone_id": "drone-1"}
```

Ровер проверяет аномалии, неизвестные и противоречивые результаты дронов,
а также явно переданные ID. Результат проверки ровера становится итоговым.
Места без наблюдений и места, которые не удалось подтвердить, остаются
`unknown`. Программа формирует по одной строке на каждый ID из карты.

Замените условные значения позы и смещения на полевые и выполните
`run`. Каталог попытки должен быть новым. В нём сохраняются
`inventory.csv`, `route.png` и JPEG по каждому осмотренному месту.

```powershell
.\.venv\Scripts\python.exe -m rover.mission run --start-px 175 73 0 --box-offset 0.35 0 --observations observations.jsonl --output attempts/case1-01
```

После достижения цели программа проверяет позу Nav2, ждёт остановки для
съёмки и анализирует три свежих кадра. Используются классы
`box_hitech` и `box_hitech_defect` из командной модели. В центральной
зоне кадра требуется единственная уверенная детекция одного класса во
всех трёх кадрах. Порог по умолчанию 0,60, его следует сверить на
кадрах площадки. Для подтверждения пустого места по отсутствию детекций
есть `--empty-verified`. Его используют после проверки, что выбранные
позы и зона кадра действительно покрывают место хранения, в том числе
на занятых и пустых примерах. Произвольные посторонние предметы модель
не распознаёт отдельным классом.

`Ctrl+C` завершает попытку и останавливает Nav2 при доступной сети.
В отдельном окне можно остановить штатную навигацию:

```powershell
.\.venv\Scripts\python.exe -m rover.mission stop
```

Nav2 исполняет уже принятую цель на борту. При потере связи с ноутбуком
команда остановки может не дойти. Для полевого прогона держите доступным
штатный останов ровера.
